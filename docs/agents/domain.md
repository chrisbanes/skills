# Domain docs

This repository has a single context.

1. Before exploring, read the root `GLOSSARY.md` and any decisions in `docs/adr/` relevant to the task. If either is absent, proceed with the existing project material.
2. Use glossary terms in issues, designs, and tests. Bring unresolved vocabulary to `/domain-modeling` when it matters to the task.
3. Surface any conflict between a proposal and an existing ADR, and identify the decision that would need to be revisited.

Use `GLOSSARY.md` for agreed domain terms and `docs/adr/` for durable decisions. Create these as domain terms or decisions are settled.
